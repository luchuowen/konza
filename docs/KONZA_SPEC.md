## 1. Thesis & Positioning

**One-line positioning:** *Konza is the vertical-transportation partner for Nairobi's next skyline — a 13-year, Fuji-authorized installer with 50 real projects behind it, from Parliament-adjacent office towers to hospital bed lifts, now building for a city zoned to build up to 75 storeys.*

**The 8-second impression a visitor should get:** "This is a real, serious, technically competent local operator — not a template site — with more completed work than either named competitor, and it takes compliance seriously." Not aspirational marketing language; verifiable substance, presented with the visual confidence of a global brand (Otis/KONE/Schindler operate here too — Konza should look like it belongs in that company, while being unmistakably Nairobi's own).

**Who the buyers are (from the proposal, unchanged — still correct):**
1. **Property developers & contractors** — compliance, delivery timelines, technical specs, multi-unit/high-rise capability.
2. **Facility & property managers** — maintenance SLAs, response times, contract clarity.
3. **Institutional & healthcare buyers** — verifiable references, safety record, procurement-friendly documentation.
4. **Homeowners** — price clarity, aesthetics, a straightforward way to book a consultation.

**Why Direction A ("Vertical City") over the other two candidates, decided without guesswork:** Konza's realest, richest, most fabrication-free asset is volume and prestige of real completed work — 50 named projects (16 direct + 34 as subcontractor) including a courthouse, hospitals, and Nairobi CBD office towers, plus three strong named testimonials spanning healthcare, commercial investment, and institutional buyers. A documentary-photography-led, credibility-and-scale-driven direction puts that asset at the center without requiring Konza to claim certifications it doesn't hold (it has no ISO/KEBS certificate of its own — only a Fuji distributor letter and a lapsed Delfar one). It also matches the proposal's own strategic thesis: closing the credibility gap with developers and institutions "in the first sixty seconds," which is exactly the audience documentary/scale-driven design wins with. The best ideas from the two directions not chosen are folded in as secondary layers: use-case-first navigation and an honestly-worded compliance module (from the "Engineered Trust" candidate), and genuine Nairobi grounding with the founding story and testimonials surfaced early (from the "Nairobi Rising" candidate).

## 4. Design System — "Vertical City" (APPROVED — client sign-off on rendered mockup, 2026-08-29)

This section supersedes any earlier palette/type draft. Everything below was built as a real, Playwright-verified static mockup (`mockups/design-final-vertical-city.html` + `mockups/design-projects-page.html`) and approved by the client ("That design is perfect, i love it"). Treat every value here as final, not a starting point.

**Palette (sampled directly from the real, extracted Konza logo — not an invented brand color):**
- `--navy-950: #0A1628` — primary background/dominant field on dark sections.
- `--navy-900: #0F2038` — secondary dark surface (proof band, footer gradient edge).
- `--navy-800: #142A47` — tertiary dark surface, card backgrounds on dark sections.
- `--red: #E8453D` — the single accent (coral-red, matches the real logo's dominant red). Used ONLY for: primary CTA buttons, the signature motif stroke, active nav/filter state, the 3px header underline, key data callouts. Never as a background field larger than a button or chip.
- `--maroon: #7A1014` — deep secondary red, matches the logo's shadow tone; used sparingly in gradients and hover-darkened states, never as a primary UI color.
- `--white: #FFFFFF` / `--paper: #F6F4F1` — true white for cards/buttons; `--paper` (warm off-white) for full light-section backgrounds — this is the "break up the dark with white" section pattern the client specifically asked for (compliance strip, projects grid, industries grid are all `--paper`, alternating with `--navy-950`/`--navy-900` dark sections).
- `--line-light: #E4E1DB` — hairline borders on light sections.
- `--slate: #5B6672` / `--slate-dark: #93A2B2` — muted body text on light / on dark respectively.

**Type — Inter + Playfair Display (sourced from the client's reference site, not invented):**
- **Playfair Display**, weight 700: every H1/H2, the testimonial blockquote, and any "serif accent" moment (e.g. `.serif` headline in a CTA band). Never used for body copy, UI chrome, buttons, or nav — headline-only, no exceptions.
- **Inter**, weights 400/500/600/700: everything else — body copy, nav, buttons, eyebrow labels, stat numbers, form fields. Eyebrow/section labels: 0.7–0.75rem, uppercase, tracking +0.08–0.14em, weight 700, in `--red` on dark or a light red tint on the darkest sections.
- Load via `next/font/google` in production (the mockup used a runtime `<link>` tag purely so the static file was self-contained for preview — do not carry that pattern into the real build; see the build workbook's Session 1).

**Logo — real client asset, not AI-generated:** the primary mark is the actual Konza logo, extracted from the live site's saved HTML export (192×192 transparent PNG). It is used directly — embedded as a real file (`public/brand/konza-logo.png`) in the build, inline-base64'd only in the throwaway static mockups for portability. **Never regenerate or redraw this logo.** If a different resolution is needed, resize/recompress the existing file (see `KONZA_MEDIA_PROMPTS.md`'s one logo-recreation prompt, which exists only for that scenario).

**Signature motif:** a simplified SVG line-drawing lift-shaft cutaway (car + rails), stroke in `--red`, centered in its own dark "How It Works" section — the single deliberate motion/attention moment on the homepage. Gentle idle pulse; respects `prefers-reduced-motion` by freezing to a static frame. Not repeated decoratively elsewhere.

**Section rhythm (non-negotiable, applies to every page, not just Home):** alternate dark (`--navy-950`/`--navy-900`) and light (`--paper`/`--white`) section backgrounds at least once per page. No page may be all-one-tone top to bottom — this was direct client feedback on the home page draft and applies to every inner page built afterward.

**Header carousels:** three independent, auto-rotating carousels in the hero (Products / Projects / Trusted By), each on its own interval (2600ms/3100ms/3600ms in the mockup, intentionally offset so they never sync) so the hero visually demonstrates the breadth of the business in the first viewport, per the client's explicit request ("the header must have 3 carousels... to show exactly what the organization offers").

**Imagery treatment:** documentary-style, not staged stock — real technicians in real PPE, real Nairobi buildings, equatorial hard-light quality. Full imagery brief and every exact filename is in Document 2 (`KONZA_MEDIA_PROMPTS.md`) — do not deviate from those filenames. Until an image lands, use the placeholder gradient classes (`.ph-products` / `.ph-projects` / `.ph-trust`) defined in the design tokens — never a broken `<img>`.

**Motion principles — fail-safe by construction:** scroll-reveal content is visible by default in CSS; a hide-class is applied only immediately before an `IntersectionObserver` starts watching an element, and removed the instant it intersects, with the whole init wrapped in try/catch. This is a deliberate correction from an earlier draft that used unconditional `opacity:0`, which meant any JS failure would permanently hide real content — never repeat that pattern. Beyond scroll-reveal: staggered project/product grids, subtle hover lifts on cards, the one signature lift-shaft moment on Home. Nothing decorative beyond that.

**Two real, fixed CSS bugs to never reintroduce (both caused fully invisible/broken sections during the design phase — verify against these specifically):**
1. Every gradient layer in a `background` shorthand must be a syntactically valid CSS color — one invalid token (e.g. a garbled hex/named-color hybrid) silently invalidates the *entire* `background` property, not just that layer, leaving the section with no background at all.
2. Any container using `max-width` + `margin:0 auto` (i.e. `.wrap`/`<Container>`) must also declare `width:100%` if it can ever be a flex child — otherwise, in a `flex-direction:column` parent, auto margins on the cross-axis suppress the default stretch behavior and the container (and everything sized as a fraction of it) collapses toward content-width.
